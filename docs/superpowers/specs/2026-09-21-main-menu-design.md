# 主菜单与游戏内返回入口设计

日期：2026-09-21

状态：用户已确认本文；进入实施计划编写阶段，产品代码尚未修改。

## 1. 目标与范围

为当前游戏提供正式启动入口，包含开始游戏、继续游戏、卡牌图鉴、设置、退出游戏；在大地图与战斗中提供返回主菜单入口。沿用羊皮纸、黑色笔触的视觉风格，按职责拆分界面、导航、设置和图鉴数据。

用户已接受第一版采用战斗起始检查点：战斗中返回主菜单后，继续游戏从本场战斗开始恢复，敌群、危险度和词缀不重新抽取。不建设任意回合战斗快照。

第一版保留现有队伍与新冒险生成规则，不增加职业选择、多存档槽、账号、云存档或图鉴解锁系统。设置限窗口模式与分辨率；不添加尚无实际系统支撑的音频分类、按键重绑定等空入口。

## 2. 现有代码约束

- `project.godot` 当前直接启动 `scenes/adventure_map_scene.tscn`；改为独立主菜单场景。
- `AdventureSession` 已负责冒险存档恢复和待处理事务；继续复用其业务规则，不在 UI 中复制。
- `AdventureSession.ensure_run()` 在无存档时创建冒险，主菜单查询状态不得调用它。
- 当前存档具有版本校验、备份恢复、旧版存档检测和待处理战斗记录；保留这些安全约束，不为菜单升级存档格式。
- 战斗已有 Esc 菜单和结算／选牌状态；返回入口接入该菜单，不再建立另一套竞争的 Esc 菜单。
- `CardData` 已包含卡面文本、详细裁定、品质、职业、正逆位信息；图鉴复用规则格式化器，不另写卡牌描述。

## 3. 主菜单

以游戏现有名称 `my_deck` 为标题，清晰排列五个主入口；旁边展示当前冒险简要信息，包括地图进度、危险度，以及是否处于待恢复战斗。无存档和异常状态显示明确解释，不显示误导性的可继续按钮。

### 开始游戏

- 没有当前存档：创建新冒险，确认持久化成功后进入地图。
- 已有当前版本冒险（包括结束的冒险）：显示覆盖确认，可取消；仅确认后创建新冒险。
- 仅有旧版存档：提示不会继承旧版进度，确认后建立新版独立存档，旧文件保持不变。
- 当前版本存档损坏且备份不可用：继续不可用；开始新游戏必须明确确认重建当前槽。
- 不支持的存档版本：禁止覆盖，解释需要匹配的游戏版本；图鉴、设置和退出仍可使用。
- 创建或保存失败：留在当前页面显示错误，不报告开始成功；保留原有可恢复进度，不因菜单切换丢失。

### 继续游戏

仅在存档有效且冒险未失败、未通关时启用。主菜单读取状态不推进游戏、不消费奖励、不重抽随机结果。

- 待处理战斗：恢复已保存的本场战斗起始状态。
- 待处理事件、奖励、商店或章节营地：进入地图并呈现对应界面，不跳过选择。
- MOVE／SHOP 等崩溃恢复沿用现有幂等恢复流程，不增加一次额外探索或重复补货。
- 主存档无效但有效备份可恢复：沿用现有恢复逻辑，并提示已恢复备份。
- 已失败或通关：继续置灰并显示冒险已结束，可开始新游戏。

### 退出游戏

主菜单直接退出应用，不触发新建冒险或保存空状态。游戏内本轮只新增回到主菜单入口，不额外重做已有关闭窗口行为。

## 4. 游戏内返回与战斗安全边界

大地图提供常驻“主菜单”按钮。返回前完成必要持久化，保留未完成事件与奖励；保存失败则保持当前场景并显示错误。切换期间屏蔽重复输入。

战斗 Esc 菜单新增“返回主菜单”。确认文案为：“返回后，本场战斗中的进度将不保留。继续游戏将从本场战斗开始恢复，敌群、危险度和词缀保持不变。”

返回必须满足：

1. 不处于行动结算、动画驱动结算或强制选牌等待中；这些状态下按钮不可用，并说明需先完成当前行动／选择。检查覆盖敌方行动，不仅检查玩家 AP。
2. 不把战斗中临时变动的角色、手牌、生命或结算队列写入冒险检查点。
3. 从有效存档建立干净的恢复状态，清理旧场景运行时引用；继续游戏时重新构建战斗，而非复用仍有运行时变动的场景对象。
4. 无有效恢复检查点时拒绝“可继续”的返回路径并说明原因，不静默重开整局。独立运行的测试战斗可明确提示无冒险存档后返回，不创建虚假继续记录。
5. 战斗结果已提交时按最新冒险状态返回，不能回退已经获得奖励的战斗，防止重复领奖。

打开 Esc 菜单本身不承诺新增全局暂停系统。返回动作以结算安全检查与防重复切换为保证。

## 5. 卡牌图鉴

独立只读页面，从主菜单进入并可返回。第一版展示项目现有玩家可获得的卡牌，包含基础牌、普通及以上品质牌，以及玩家可持有的生成牌和诅咒牌；不收录敌人专用与诊断样例牌。

- 支持职业、品质筛选与卡名搜索；职业筛选按卡牌标注归属及多职业归属匹配，中立单独归类。
- 品质顺序为基础、普通、稀有、史诗、传说，不直接采用枚举整数排序。
- 列表显示名称、费用、品质、职业及插画或占位；详情显示严格卡面文本与详细裁定。
- 德鲁伊双面牌以一条记录展示，支持正位／逆位切换并展示对应名称、费用与规则；搜索匹配两个名称。
- 不依赖战斗上下文，不调用打牌或支付接口；武器、距离等动态数值保持规则表达，不伪造具体值。
- 没有插画或详细裁定时使用明确占位，不隐藏卡牌，不复制过时文案。
- 使用显式资源目录清单，确保导出后可用；不以运行时扫描源码目录作为唯一发现方式。图鉴目录与奖励池分开，避免把基础牌加入掉落。

## 6. 设置

独立页面和独立 `user://` 配置文件，不写入冒险存档。

- 窗口／全屏模式。
- 窗口分辨率预设：1280×720、1600×900、1920×1080。按当前屏幕可用区域约束窗口，保留已有画布缩放逻辑。
- 应用、恢复默认和返回；未应用修改离开时丢弃，不影响已保存设置。
- 显示设置应用后提供限时确认，15 秒未确认自动回退；只有确认后持久化。全屏时窗口尺寸选项禁用但保留上次窗口设置。
- 缺失、损坏或不支持的设置值回退安全默认值；写入失败明确提示，不声称已保存。
- 无窗口的诊断模式可测试数据逻辑，不依赖真实显示设备。

## 7. 视觉与交互

使用现有纸纹资源和黑色笔触语言，保持高对比按钮、清晰标题与留白，不引入新世界观或未经确认的游戏名称。主菜单以标题与纵向操作区为核心；图鉴采用筛选、滚动列表和详情区；设置采用简短表单。

布局使用容器适配已有 1280×720 基准及更宽窗口。支持鼠标、键盘焦点、确认和返回；Esc 优先关闭最上层弹窗，其次返回上级页面。所有禁用按钮有对应状态说明，错误信息不会只输出到控制台。

## 8. 模块职责

- 主菜单场景／控制脚本：按钮、冒险摘要、确认和错误展示。
- 导航协调模块：场景切换、防重复请求、接收保存／恢复结果。避免堆进地图或战斗控制器。
- `AdventureSession`：新增窄接口暴露可继续状态、保存返回和检查点恢复；持久化仍由现有存储模块负责。
- 设置服务与设置界面：分别负责校验／持久化／显示应用，以及用户交互。
- 图鉴目录与图鉴界面：分别负责完整资源清单／筛选，以及只读展示；规则文字复用现有格式化器。
- 地图与战斗场景：只接入返回按钮、必要安全状态与协调接口；不承担图鉴或设置逻辑。

不为主菜单增加无关战斗规则重构，也不修改六边形地图、危险成长、卡牌数值或商店随机序列。

## 9. 验收与验证

1. 默认启动进入主菜单；仅浏览图鉴／设置不生成冒险、不覆盖存档。
2. 无存档、新建、覆盖取消、保存失败、有效存档、备份恢复、损坏／旧版／未来版本、通关／失败状态均有诊断覆盖。
3. 大地图返回再继续时位置、危险度、队伍、背包、随机序列和待处理选择保持一致。
4. 战斗中改变生命、手牌等后返回，继续恢复本场起始状态；敌群、危险和词缀不变；同进程恢复与重启恢复一致。
5. 结算和强制选择期间不能返回；战斗结果提交后返回不会复活旧战斗或重复奖励。
6. 图鉴含基础牌且不污染奖励池；筛选、逆位、详细裁定、缺图占位正确，资源引用可用于导出。
7. 设置应用／取消／超时回退／重启加载／损坏回退正确，且不影响冒险文件。
8. Godot 编辑器导入、相关自动诊断、现有冒险与战斗回归通过；真实图形模式检查各页面、弹窗、焦点与缩放，不只依赖无头测试。
