# 主菜单实施与验证记录

日期：2026-09-21

## 实现范围

- 默认启动主菜单：开始游戏、继续游戏、卡牌图鉴、设置、退出。
- 72 张玩家卡牌的只读图鉴；职业／品质／名称筛选、德鲁伊逆位与详细裁定。
- 独立窗口／全屏和三档分辨率配置；15 秒预览确认、取消／超时／保存失败回退。
- 地图顶栏和事件／奖励弹窗返回入口；战斗 Esc 菜单返回入口与确认。
- 战斗返回从已保存的本场起点恢复；敌群、危险快照、随机状态不重抽。
- 新建保存失败不替换当前冒险；场景切换失败保留实时战斗资源引用。

未修改卡牌数值、地图生成规则、危险成长或商店随机数规则；未增加任意回合战斗快照。

## 独立代码审查

一名独立审查智能体审查了完整实现范围，发现 1 项 Important，无 Critical 或 Minor。问题为存档写入器未检查临时文件的写入／刷新完成情况，可能将不完整保存当成成功。本轮修复保留写入成功检查，并在关闭后核对临时文件内容，核验失败时不轮换主存档或备份，也不发布新冒险。

回归使用独立子进程的文件大小限制，实际触发打开后写入失败，不填满用户磁盘。大体积直接写入和小体积缓冲刷新两种路径均先复现失败，再修复通过；测试同时检查内存引用与主／备份字节不变。Windows 不运行此 POSIX 专属故障注入，常规存档失败与生命周期测试仍运行。

实现依据：写入方法提供成功标记，但底层刷新接口并不保证更新错误状态，因此增加关闭后的读回核验。[FileAccess 文档](https://docs.godotengine.org/en/stable/classes/class_fileaccess.html#class-fileaccess-method-store-string)、[Godot Unix 文件实现](https://github.com/godotengine/godot/blob/master/drivers/unix/file_access_unix.cpp)。

## 验证中发现并修复

1. 诊断隔离参数覆盖了手工注入的 Session 存储，导致旧恢复诊断加载空状态。仅对真正的 autoload 应用隔离，旧恢复诊断重新通过。
2. 图鉴默认选中背景过浅，白色文字对比度不足。对比度回归先失败，再以深色选中背景修复。
3. 返回主菜单重载检查点后，若场景加载失败，运行中的战斗仍需要原资源引用。新增失败切换回归，导航失败时恢复原 run 与 scenario，回归转绿。
4. 视觉诊断未显式隔离旧版槽，导致新游戏确认保护被触发而测试忽略返回值。添加成功断言并隔离旧槽后重拍，验证菜单正确显示可继续进度。
5. 独立审查发现临时文件写入失败未被处理。真实受限写入诊断复现了错误发布新冒险及主存档改变，修复后两种写入失败均被拒绝，原进度和备份保留。

## 明确的行为裁定

战斗已经结束但尚未提交结果时，先通过现有战斗结果按钮完成结算，再从地图返回主菜单。这样不会把胜利回退为未打完的战斗或重复奖励；代价是多一次进入地图的操作。

独立审查未裁定的范围，由主实施者作以下裁定：

- 保留已记录的旧战斗退出泄漏警告，不扩展到战斗资源生命周期重构；若其不只发生于退出，风险是长期运行内存增长。
- Windows／Android 仅标记为未验证，不以 macOS 或 PCK 结果代替平台验收；风险是平台显示或打包问题需后续修复。
- 既有战斗平衡、重开语义和奖励规则不在本轮改写；若旧规则存在问题，风险是原问题仍保留。
- 独立审查者无法打开截图，不宣称其完成了视觉认证；采用主实施者检查截图及双分辨率图形测试的结果。风险是缺少第二人的审美／视觉复核。

延期的 Minor：无。

## 已知限制

- 战斗相关现有诊断以及复用完整战斗场景的新诊断仍会报告 ObjectDB、Resource 或 RID 退出泄漏警告。这些与功能失败分开记录；未在本轮扩大范围清理战斗资源生命周期。
- 尚未验证 Windows／Android 独立安装包和平台特定显示模式；PCK 验证不等同于完整平台发布验证。
- 尚无额外裁定或专属插画的卡牌使用现有文本和占位，不编造规则。
