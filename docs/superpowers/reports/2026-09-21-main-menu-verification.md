# 主菜单实施与验证记录

日期：2026-09-21

## 实现范围

- 默认启动主菜单：开始游戏、继续游戏、卡牌图鉴、设置、退出。
- 72 张玩家卡牌的只读图鉴；职业／品质／名称筛选、德鲁伊逆位与详细裁定。
- 独立窗口／全屏和三档分辨率配置；15 秒预览确认、取消／超时／保存失败回退。
- 地图顶栏和事件／奖励弹窗返回入口；战斗 Esc 菜单返回入口与确认。
- 战斗返回从已保存的本场起点恢复；敌群、危险快照、随机状态不重抽。
- 新建保存失败不替换当前冒险；场景切换失败保留实时战斗资源引用。

未修改卡牌数值、地图生成规则、危险成长或商店随机数规则；未增加任意回合战斗快照。

## 验证证据

环境：Godot 4.7.2 Steam，macOS，OpenGL Compatibility / Apple M5。使用独立诊断存档及显示配置，不覆盖真实进度。

| 验证 | 结果 |
|---|---|
| 编辑器无头导入 | 通过，无脚本或解析错误 |
| 最终全部非视觉诊断 | 60 / 60 通过，0 失败；含新增真实场景冒烟测试 |
| 新增真实场景冒烟测试 | 通过：开始 → 地图 → 战斗 → 主菜单 → 继续同场 → 再返回 → 退出 |
| 五个菜单功能诊断 | 存档、导航、图鉴、设置、返回均通过 |
| 实际图形模式显示设置诊断 | 通过 |
| 双分辨率视觉诊断 | 通过；1280×720、1920×1080 |
| 导出 PCK 中的图鉴诊断 | 通过；显式目录资源在导出后可加载 |
| 独立平台安装包 | 未验证：本机没有导出模板 |

独立代码审查结果将在本记录中补齐。

## 验证中发现并修复

1. 诊断隔离参数覆盖了手工注入的 Session 存储，导致旧恢复诊断加载空状态。仅对真正的 autoload 应用隔离，旧恢复诊断重新通过。
2. 图鉴默认选中背景过浅，白色文字对比度不足。对比度回归先失败，再以深色选中背景修复。
3. 返回主菜单重载检查点后，若场景加载失败，运行中的战斗仍需要原资源引用。新增失败切换回归，导航失败时恢复原 run 与 scenario，回归转绿。
4. 视觉诊断未显式隔离旧版槽，导致新游戏确认保护被触发而测试忽略返回值。添加成功断言并隔离旧槽后重拍，验证菜单正确显示可继续进度。

## 明确的行为裁定

战斗已经结束但尚未提交结果时，先通过现有战斗结果按钮完成结算，再从地图返回主菜单。这样不会把胜利回退为未打完的战斗或重复奖励；代价是多一次进入地图的操作。

## 已知限制

- 战斗相关现有诊断以及复用完整战斗场景的新诊断仍会报告 ObjectDB、Resource 或 RID 退出泄漏警告。这些与功能失败分开记录；未在本轮扩大范围清理战斗资源生命周期。
- 尚未验证 Windows／Android 独立安装包和平台特定显示模式；PCK 验证不等同于完整平台发布验证。
- 尚无额外裁定或专属插画的卡牌使用现有文本和占位，不编造规则。
