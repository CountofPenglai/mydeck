# 畸变系统实现记录

更新时间：2026-07-26

本文记录 `诅咒.md` 与 `敌人.md` 中统一畸变规则的当前实现。设计目标以外部文档为准；本页用于说明代码事实、已落地的基础交互与后续扩展边界。

## 数据与所有权

- `CardData.mutation_fields` 保存结构化字段 ID，卡面使用 `get_mutation_label()` 生成 `畸变~字段、字段`。
- `DistortionCatalog` 保存 6 个低位字段、6 个高位字段、显示文本和里程碑 `2/5/8/11`。
- `CharacterState` 保存畸变进度、已领取里程碑、永久字段和恩典次数。
- `DistortionBattleState` 属于单个 `BattleUnitState`，保存字段来源计数、显化进入顺序和单位级限次标记。
- 共享 `CardData` 和怪物牌 `.tres` 不保存回合次数、字段是否触发或显化寿命。

## 回合开始

1. `BattleUnitState.start_turn()` 快照旧显化牌并重置回合计数。
2. 辐照等旧字段结算回合开始触发。
3. 兽心把基础抽牌改为 3；启明消耗 1 咒波并追加 1 张。
4. 快照中的旧显化牌依次通过附魔区到弃牌堆接口衰退。
5. 控制器按衰退数量结算一段生命损失。
6. 玩家进入 `MANIFEST_PENDING`，可勾选 0 至 2 张；敌人执行意图中预先锁定的选择。
7. 显化完成后才开放行动阶段。

额外显化不使用每回合两张限制。启明之瘤从牌库调用同一显化入口；披夜薄膜调用统一解放入口。

## 字段实现

基础版已接入以下字段效果：

- 低位：鞭笞、空目、附肢、觅血、泥肺、兽心。
- 高位：岩鳞、灼喉、披夜、启明、辐照、奔踏。

这些效果复用控制器伤害、治疗、状态、移动、地表和牌区接口。临时与永久来源授予同一字段；同字段只生效一次，但多个来源仍分别显示和衰退。

## 战斗内 UI

- 顶部入口显示诅咒数量、畸变字段数、负荷和咒波。
- 诅咒区弹窗按单位显示报/果、封印状态、永久字段、显化牌来源和畸变行动。
- 玩家回合开始若有可显化牌，弹出独占选择窗；选择完成或明确跳过后才进入行动阶段。
- 敌人情报栏显示计划显化字段及预计衰退生命。

## 战斗外 UI

- 大地图队伍条为每个角色提供“诅咒与畸变”入口。
- 达到未领取里程碑时按钮使用金色边框和“奖励待选”文本高亮。
- 弹窗显示负荷、业/报/果、封印、成熟度、里程碑轨道、永久字段和确定性三选一。
- 玩家可放弃三个字段选择恩典；力量、敏捷、智力各加 1，最大生命增加时当前生命同步增加。
- 畸变奖励不进入战后奖励事务，不会覆盖或跳过战斗后的卡牌选择。

## 存档

- 冒险存档版本为 4。
- v3 存档可加载，新增字段使用安全默认值。
- v4 保存永久字段、已领取里程碑、恩典次数和恩典产生的属性加值。

## 验证

- `curse_system_check.tscn`：字段映射、重复来源、衰退、解放、恩典、赝作阈值和战斗显化选择窗。
- `adventure_system_check.tscn`：v3→v4 迁移、存档往返、确定性三选一、地图高亮与战后奖励并存。
- `chapter_one_enemy_check.tscn`：怪物卡池与公开意图。
- `battle_flow_check.tscn`：回合与行动队列邻接回归。
- `diagnose_battle_load.tscn`：全资源扫描和战斗 UI 实例化。

## 后续边界

- `MonsterManifestStatus` 文件暂时保留用于历史追溯，但活动资源和效果脚本不再引用。
- 当前负面状态识别由统一状态 ID 白名单承载；状态类型继续增加时，宜在 `StatusEffect` 增加明确的正负面分类字段。
- 若未来实现强类型牌区事务，应替换现有数组入口，但不得改变显化衰退逐张弃置、汇总失血和字段来源注销的规则。
